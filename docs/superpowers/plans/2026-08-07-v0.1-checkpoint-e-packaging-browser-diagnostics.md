# V0.1 Checkpoint E Packaging and Browser Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Strengthen V0.1 checkpoint reproducibility and convert the opaque Chromium timeout into explicit environment-policy evidence while preserving every unresolved release gate.

**Architecture:** Keep the application/runtime slice unchanged. Add a repository-native release packaging boundary that archives an exact commit and emits a cloneable Git bundle with an explicit `HEAD`, then make browser qualification diagnose managed navigation policy before attempting IndexedDB execution. Feed the IndexedDB qualification result into the V0.1 verifier as pass, fail, or blocked evidence.

**Tech Stack:** Python 3.13, Git bundle/archive, pytest, Chromium 144, IndexedDB benchmark, existing V0.1 verifier.

## Global Constraints

- License remains `AGPL-3.0-only`.
- Canonical release branch remains `bootstrap/v0.1`.
- No application feature scope is added in Checkpoint E.
- Runtime defects are handled with RED -> GREEN TDD.
- A Git bundle must be directly cloneable without requiring the recipient to infer the branch manually.
- IndexedDB evidence must still come from a real browser origin. An environment-policy blocker is evidence of a blocker, not evidence that the benchmark passed.
- Android and Windows storage qualification remains mandatory before closing `R01-T035`.
- Dependency-lock, static-analysis, PWA-build, Playwright, axe and scanner gates remain unresolved unless freshly executed.
