# V0.1 Bootstrap + Customer Golden Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a reproducible V0.1 repository bootstrap and a verified Customer vertical slice spanning backend domain/API, synchronization contracts, local-first frontend persistence scaffolding, CI, and operations baseline.

**Architecture:** The server is a Python modular monolith with FastAPI, Pydantic, SQLAlchemy 2, Alembic, a mutation log, idempotency ledger, incremental change feed, and capability-based authorization. The client is a React + TypeScript + Vite PWA with Dexie as the local repository, a durable mutation queue, and a pull/merge sync coordinator. PostgreSQL is authoritative in LAN/Cloud, while the browser remains independently operable offline.

**Tech Stack:** Python 3.13, FastAPI, Pydantic 2, SQLAlchemy 2, Alembic, PostgreSQL 18.4 canonical server target, React 19, TypeScript 5.8+, Vite 8, Dexie 4, Tailwind CSS 4, pytest, Vitest/Playwright once dependencies are installable, Docker Compose.

## Global Constraints

- License: `AGPL-3.0-only` for Core and official applications.
- Offline First and Local First are non-negotiable.
- REST JSON + deterministic OpenAPI is the HTTP contract.
- IDs for synchronizable entities are UUIDv7-compatible strings.
- Authorization is deny-by-default and capability scoped.
- Sync mutations are idempotent and acknowledgement/cursor state advances durably only after local merge succeeds.
- PostgreSQL is the production server database. SQLite is allowed only as a unit-test surrogate where PostgreSQL-specific behavior is not under test.
- No production code without a failing test first for behavioral features.
- The implementation must not require Internet access to perform the testable backend slice in this environment.
